# Проверка отчёта `deep-research-report.md`

Дата проверки: 26 августа 2026 года.

Отчёт содержит 250 исторических пользовательских сигналов, а не 250
одновременно воспроизводимых дефектов текущего Powerstral. Поэтому пункты были
проверены как классы отказов: уже закрытые upstream-проблемы не реализовывались
повторно, внешние ограничения тарифов и качество модели не выдавались за
исправляемый код CLI, а подтверждённые пробелы текущего исходника получили тесты.

## Исправлено в этой ревизии

- Fast working memory теперь сохраняется приватно в metadata сессии и
  восстанавливается после `/resume`, а не только после compaction в памяти
  процесса.
- Статус памяти передаётся отдельным typed event и больше не маскируется под
  reasoning/assistant output, что сохраняет корректную ACP-проекцию.
- `permission = "never"` остаётся жёстким запретом при auto-approve и autonomous;
  Plan-профиль не получает shell, PC, Chrome CDP, память или субагентов.
- Reasoning-only stream без ответа или tool call считается незавершённым;
  полностью пустой технический ответ сохранён для совместимости старых
  tool-call сценариев.
- Generic/OpenAI-compatible backend принимает SSE `data:{...}`, нормализует
  `tool_call.type = null`, понятно отклоняет неизвестный type и умеет отключать
  streaming, `stream_options` и `reasoning_effort` по возможностям провайдера.
- Ошибка 429 сохраняет сообщение провайдера и `Retry-After`.
- Managed shell ограничивает отдельный лог 64 MiB и набор сохранённых логов
  512 MiB; старые orphan-логи удаляются первыми, переполнение завершает процесс.
- Esc немедленно переводит ручную shell-команду в `Stopping`; раннее событие todo
  больше не падает, если TaskStatusBar ещё не смонтирован.
- Windows ConPTY filter отбрасывает служебные device/color reports и декодирует
  win32-input records, не печатая escape-последовательности как пользовательский
  текст.
- Автообновление не выполняет команды upstream `mistral-vibe`; справка и ссылки
  указывают на Powerstral. Добавлен `SECURITY.md`.

## Подтверждено существующей реализацией

В текущем дереве уже имеются: OAuth и API fallback, model picker, строгие
таймауты и завершение дерева процессов, очередь ввода во время занятого агента,
compaction/resume, skills и custom slash-команды, MCP/hooks/ACP, planning и
clarifying questions, субагенты, web search/fetch, image input, OpenTelemetry,
глобальная память, task status, Windows PowerShell/Git Bash tools и
OpenAI-compatible provider configuration. Эти области проверяются их
существующими модульными/контрактными тестами.

## Не является исправлением исходника CLI

- лимиты, PAYG, возвраты, содержание подписок и доступность моделей управляются
  внешним сервисом;
- субъективное качество модели и исторические сравнения с Claude не могут быть
  устранены патчем harness;
- интеграции и feature requests, уже закрытые upstream или зависящие от чужого
  IDE/сервиса, требуют отдельного воспроизведения на актуальной версии.

Такая классификация обязательна: объявлять внешние или исторические пункты
«исправленными» без воспроизведения было бы тем самым неподтверждённым
утверждением, против которого направлен отчёт.

## Проверка

Релевантные suites охватывают agent loop, autonomy, permissions, compaction,
session logger/loader, backend adapters, app-server/ACP projection, TUI,
PowerShell/Windows shell, updater и память. Для Windows известны upstream-тесты,
которые сами содержат POSIX-only assumptions (`fcntl`, `sleep`, `time.tzset`);
они учитываются отдельно от продуктовых регрессий.
