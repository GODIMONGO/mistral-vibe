# Проверка отчёта `mistral_vibe_minusy.md`

Дата проверки: 26 августа 2026 года.

## Метод

Приложенный список использован как входной аудит, а не как набор исполняемых
инструкций. Каждый пункт сопоставлялся с текущим исходным кодом Powerstral и
проверялся тестом или чтением конкретного контракта. В список одновременно входят
исторические дефекты upstream Mistral Vibe, ограничения внешних моделей/API,
пожелания уровня IDE и повторяющиеся общие утверждения. Поэтому количество строк в
отчёте не равно количеству воспроизводимых дефектов текущей версии.

## Исправленные воспроизводимые дефекты

- Неизвестная рабочая папка больше не получает небезопасный выбор «доверять» по
  умолчанию. Диалог по умолчанию выбирает отказ.
- Создание или выбор Git worktree запрещено до проверки доверия к исходной папке,
  поэтому Git не запускается в непроверенном репозитории ни через app-server, ни
  через standalone CLI.
- Явное `permission = "never"` имеет абсолютный приоритет и не может быть
  отменено семантическим разрешением инструмента или auto-approve.
- Снимок конфигурации в `meta.json` очищается от прямых ключей, заголовков и
  значений окружения, включая произвольные overrides профиля агента; имена
  ссылочных переменных остаются для диагностики.
- `LOG_MAX_BYTES` реально ограничивает текущий лог: при достижении лимита файл
  безопасно обнуляется на месте, включая Windows, где переименование открытого
  файла ненадёжно.
- Поток `cmd.exe` декодируется OEM-кодировкой Windows с инкрементальным декодером;
  UTF-8 для Git Bash/POSIX не изменён.
- Generic/OpenAI-compatible backend теперь использует общий настроенный бюджет
  повторов и числовой `Retry-After`, не засыпая за пределами лимита.
- Reviewer не может подтвердить завершение только текстом
  `EVIDENCE_CHECKED`: для PASS требуется хотя бы один успешно наблюдённый вызов
  evidence-инструмента (`read_file`, `grep` или `web_search`) в независимом
  запуске reviewer; загрузка skill и прочие служебные вызовы доказательством не
  считаются.
- Исходная пользовательская цель получает отдельный ограниченный бюджет при
  compaction, а оставшийся бюджет сохраняет самые свежие уточнения. Это снижает
  дрейф цели и повторение уже выполненных действий.
- `/tasks` показывает текущие выполняемые, завершённые, ожидающие и отменённые
  задачи; `/tasks clear` по-прежнему очищает только отображение без LLM-вызова.

## Уже присутствовало в проверяемом исходнике

В текущей ветке уже реализованы bounded fast working memory и постоянная global
memory, восстановление памяти после resume, видимые события загрузки памяти,
планирование с advisor/worker/reviewer, ограниченный swarm, таймауты управляемых
shell-команд, Windows ConPTY-фильтр, управление ПК/Chrome, web search со статусом,
провайдерские capability-флаги, SSE-разбор generic backend и fallback моделей.
Эти пункты проверяются профильными тестами и не дублировались отдельными
«исправлениями».

## Не являются локальными дефектами Powerstral

- качество, размер контекста и фактическое внутреннее рассуждение удалённой
  модели;
- тарифы, квоты, 402/429, доступность OAuth и политика API-провайдера;
- лицензирование моделей и внешних наборов данных;
- отсутствие возможностей конкретной IDE, мобильного клиента или стороннего
  сервиса;
- требования создать универсальную IDE, обучить новую модель или обеспечить
  абсолютную безошибочность.

Такие ограничения нельзя честно «исправить» патчем CLI. Powerstral может только
делать их явными, применять fallback, ограничивать ресурсы и проверять наблюдаемые
результаты.

## Проверка

Для исправлений добавлены регрессионные тесты безопасности, compaction, сессий,
Windows-декодирования, task status и reviewer provenance. Полный тестовый набор на
нативном Windows также фиксирует отдельный upstream-долг: POSIX-only тесты,
которые напрямую ожидают `bash`, нельзя считать кроссплатформенными до их
параметризации или изоляции в Linux CI.

Фактические результаты этого запуска:

- объединённый критический набор: 270 passed;
- повторный набор после независимого review: 140 passed;
- Pyright для всех изменённых критических модулей: 0 errors;
- Ruff check/format и `git diff --check`: passed;
- полный Windows pytest: 9637 passed, 71 skipped, 330 failed; падения собраны в
  POSIX-only/платформенных тестах и не маскируются как успешный прогон;
- полный Windows Pyright: 29 POSIX-stub ошибок (`pty`, `termios`, Unix signals),
  при этом изменённые модули проходят отдельно;
- независимый повторный review после исправления трёх найденных обходов: PASS.

Полный pre-commit нельзя было завершить в этой Windows-среде: подготовка
`action-validator` требует отсутствующий MSVC `link.exe`. Остальные структурные
хуки, YAML/TOML, whitespace, Ruff и форматирование прошли; `typos` отдельно
обнаружил существующий false positive в тестовой строке с незавершённой
slash-командой.
